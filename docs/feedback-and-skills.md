# 提醒反馈与技能使用记录

报告保存后可以记录“有用”“已采纳建议”或“需要纠正”，并补充文字。快报可以记录“有用”“重复”“与我无关”或“以后也关注”。这是用户明确给出的使用反馈，不是模型自评，也不自动改写报告、启用技能或调整监测。

## 看反馈，再决定怎样调整

监测记录保留每次快报的反馈。每条快报以最近一次反馈计数，重复提交不会重复增加条数。标记重复、无关或希望继续关注时，会出现相应的检查建议；你仍需打开监测方案，修改并预览范围、提醒标准、频率或接收位置，再确认启用。建议不会直接成为新配置。

检查记录区分基线建立、没有新增变化、检查失败和研究待恢复。快报区分本地保存、发送中、已取得消息回执、发送失败和结果未确认。取得回执不表示对方已读；结果不明时不自动重发。既有默认本地收件箱和 Hermes 显式确认机制继续保留。

## 看经验是否进入了后续研究

“经验与技能”增加按版本的任务记录：某个技能实际加载进多少项任务上下文，其中多少形成已保存报告，以及关联报告收到的反馈。仅出现在可选技能目录中不计为加载。停用和回退后，旧任务保留原快照，记录仍对应原版本。

这些数字说明技能何时被带入任务，不能证明它造成了更准确的分析。关联报告的反馈也不能单独归因于某个技能。可以结合原稿、来源和用户纠正决定继续使用、修改、停用或回退；不增加每份报告的强制评分、审稿或循环改写。

## CLI 与接口

- `manage feedback save --project PROJECT --data YOUR_PRIVATE_FEEDBACK.json` 保存明确反馈。
- 报告反馈字段为 `kind: "report"`、`target: "RUN_ID"`、`rating` 和可选 `note`。
- 快报反馈字段为 `kind: "monitor"`、`target: "DELIVERY_ID"`、`context: "MONITOR_ID"`、`rating` 和可选 `note`。
- `rating` 支持 `useful`、`duplicate`、`irrelevant`、`follow`、`adopted`、`needs_correction`。页面按报告或快报展示相应选项。
- `manage feedback list` 读取本项目反馈；`manage feedback usage` 读取技能版本记录；`manage feedback suggestions` 的 JSON 需要 `monitor_id`。
- HTTP 使用 `/api/feedback/{save,list,usage,suggestions}`。写入只接受 POST；沿用本地服务的认证、Host 与 Origin 检查。

两套 CLI 前缀分别为 `georisk-agent` 与 `market-entry-agent`，也可用虚拟环境 Python 的模块入口。反馈必须指向本产品、本项目已经保存的报告或快报。反馈文字可能包含私有内容，留在工作空间，不进入公共证据包或自动公开的技能。

## 本轮验证范围

两套本地临时监测在操作者确认后各连续运行 10 分钟，每 2 分钟检查并汇总，首次只建立基线；分别获取 IMO 红海和欧盟 CBAM 官方页面。各完成一次基线和四次无变化检查，没有快报，随后暂停且进程退出。本轮没有出现真实新增重大事件，也没有向真实账号发送消息，因此不能据此声称已经证明提醒研判质量、外部交付或长期稳定性。

变化筛选、失败退避、免打扰和不确定发送回执继续通过明确标记的合成回放验证。真实历史报告用于检查经验候选生成、版本操作和反馈隔离；加载统计用离线演示走通，并明确标记为验收反馈，不冒充真实用户评价或模型质量改善。
