# 配置与日常使用

在研究工作台点“配置模型与来源”，或打开“运行与边界”。先保存所选模型的接口、名称和参数，再单独测试连接；填写设置、配置可读、请求成功是三个不同状态。测试连接只发送一段诊断短句，最多一次模型请求，不读取企业或知识库材料。

## 模型设置和密钥

可以继续沿用 `AGENT_MODEL_BASE_URL`、`AGENT_MODEL_NAME` 和 `AGENT_MODEL_API_KEY`。网页保存的非敏感设置放在本工作空间的 `model-profile.json`，只影响该工作空间；默认不把输入的密钥写入磁盘。密钥不会通过状态接口回显，浏览器输入框在保存后清空，不写入浏览器本地存储。

默认输入的密钥仅供当前服务进程使用，重启后需重新提供；另行启动的 worker 看不到该进程内的密钥。长期运行可以给 worker 配置自己的环境变量，或明确勾选在本机工作空间保存密钥。勾选后文件包含未加密的密钥，按私有配置管理；POSIX 文件权限为仅文件所有者可读写，Windows 仍取决于用户目录权限。不要共享该文件或把运行工作空间当作开源源码提交。

修改模型接口时，不会自动把另一个接口的环境变量密钥带到新地址。保存后要重新测试；修改输入但尚未保存时，页面不允许拿旧配置冒充新配置的连接测试。测试只说明该时刻请求成功，后续仍可能受网络、额度和服务状态影响。

新任务和显式恢复任务使用该工作空间当时的模型配置；已有任务的资料范围、提示词、技能和调用预算仍使用其保存规则。运行中的模型实例不会因为编辑配置被中途替换。

## 来源与可选工具

在页面选择官方来源并添加。添加只保存明确的来源配置，不立即抓取，也不自动创建或启动监测。已经登记且与示例不同的同名配置不会被示例静默覆盖；如需修改，按原有来源管理方式核对后处理。查看最近获取、缓存与失败状态后，再决定刷新或研究。

Office、PDF、MCP 搜索和 Hermes 仍是可选连接。页面显示是否找到配置的文件或程序；这不等于已通过实际转换、搜索或发送。完整设置继续见相关工具文档。

## 持续运行状态

worker 增加独立的运行记录：最近心跳、本轮开始、最近一次结束、错误类别与停止状态。页面按需读取，不启动新的后台进程。近期心跳只表示进程仍有回应，不代表报告已完成；长时间没有心跳显示可能停止，不能据此断定外部没有变化。

启动一次检查后退出：`worker --once`；持续执行仍使用 `worker`，交给自己选择的进程管理方式。机器休眠、退出进程或关闭宿主时，监测不能继续。网页、worker 和其他进程必须指向同一个私有工作空间，分别核对模型密钥是否可用。

CLI 的 `doctor` 读取配置、来源、可选工具和 worker 状态，不调用模型。只有显式加 `--test-model` 才进行一次模型连接测试。两个产品使用各自的 CLI 前缀；Windows 可以用虚拟环境 Python 的模块入口，不需要激活脚本或 WSL。

## 已保存报告直接导出 Word

基础安装可以从网页直接下载可编辑 DOCX，或用原有 `export RUN_ID --output YOUR_PRIVATE_REPORT.docx` 命令导出。新内置路径保留完整报告文字、来源、标题与列表，不调用模型；明确编号保留原值。复杂 Markdown 表格和行内记号仍可能按文字保留，不是企业排版模板。

如果明确配置了 `AGENT_OFFICECLI`，命令行继续使用原有 OfficeCLI 适配器；网页的直接 Word 下载使用内置路径。已有 DOCX、Markdown 和 JSON 导出及 Office 导入保持可用。文件包含报告本来引用的材料，按私有成果管理；已有导出文件不覆盖。

## 与自己的 MCP 客户端衔接

默认只读接口新增 `project_overview`，读取项目研究档案；`knowledge_citation` 按报告任务读取其固定版本的文档片段。两者沿用产品和项目范围检查、分页与删除撤权。运行任务仍要显式开启 `--allow-runs`，不会因读取档案自动获得执行或外部发送权限。

## 安装后的验证

`python scripts/verify_project_research.py` 从已安装包走知识检索、引用旧版本、真实本地 HTTP 配置与 Word 下载、反馈、默认只读 MCP、显式离线任务执行，以及 worker 的启动、完成和停止。模型步骤使用明确标记的脚本替身，验收反馈也标为测试；没有付费模型请求或外部消息。本轮真实历史报告和确认后的十分钟监测另行记录，不能用该脚本替代真实模型文字质量或长期运行证据。
